# 미끼주의보: 실전 대응 훈련 (MVP)

## 사용자 목표
예고 없는 연락이나 특정 상황에서 **실제로 필요한 안전한 대응 행동을 선택하는 능력**을 훈련한다. 상대가 누구인지 맞히는 게임이 아니라, 출처가 불확실해도 돈·정보 제공을 보류하고 필요하면 별도 경로로 확인하며 직접 판단한 행동을 평가한다.

## UX / 기존 기능 보존
- 홈의 훈련 진입 → 시작 안내 (/roleplay) → **훈련 방식 선택** (/roleplay/mode). **실전 훈련**은 상황을 미리 알리지 않고 바로 /roleplay/chat으로 이동한다.
- 기존 시나리오 자동 관찰 → **사례로 먼저 배우기** (/roleplay/case); 원래 관찰형 데이터와 리뷰는 보존.
- **상황별 연습**은 /roleplay/select에서 원하는 주제를 선택한 뒤 AI 문자 (/roleplay/chat?topic=...)로 이동한다. **사례로 배우기**는 별도의 관찰형 화면 (/roleplay/case)을 유지한다. 같은 대화 엔진과 행동 평가를 쓰며 실전 훈련의 상황만 서버가 예고 없이 고른다. 두 방식 모두 정상/사칭 여부는 서버에서 무작위로 결정한다.
- OX 퀴즈와 가족 초대/질문 화면 유지.
- 미구현 전화 기능은 진짜 발신·녹음·분석이 아니라고 명확히 안내.

## 훈련의 교육 설계
- **9개 주제(가족·택배·은행·청첩장·부고·교통 과태료·저금리 대출·단기 일자리·건강검진)**, 주제마다 정상/사칭 1쌍, 총 18개 역할. 첫 메시지는 고정 대본이 아니라 AI가 매번 생성하며, 같은 주제의 정상/사칭에는 동일한 사건 조건과 중립 프롬프트를 적용해 정답을 드러내지 않는다. [조사 근거와 대화 흐름](TRAINING_SCENARIOS_RESEARCH_2026-11-05.md).
- Gemini/Groq 중 사용 가능한 모델은 각 역할의 **자연스러운 대화 및 구조화된 진행 상태**를 생성한다. 진실, 독립 확인 결과, 행동 기록, 실제 종료 판정, 피드백은 프로그램이 결정한다.
- 대화의 맥락과 남은 요청을 기억하고, 자연스럽게 끝난 경우 더 이상의 인사 반복 없이 마지막 문자 뒤에서 종료한다. 기본 대화 엔진은 [v3](TRAINING_ENGINE_V3.md), 휴대전화의 행동 흐름은 [v4 휴대전화 패널](TRAINING_PHONE_FLOW_V4.md) 참조.
- UI는 일반 메신저처럼 전체 화면 채팅으로 구성하고 상단 휴대전화 아이콘을 통해 **연락처·전화·설치된 앱·문자**를 선택할 수 있다. 첫 패널에 정답 선택지를 노출하지 않는다.
- 훈련 시작 시 휴대전화 아이콘의 위치와 기능, **대화 도중에도 사용 가능하며 확인 후 다시 돌아올 수 있음**을 알려주는 간결한 안내 시트를 띄운다. **다음부터 이 안내 보지 않기**를 체크한 경우에만 브라우저 localStorage로 재표시를 막는다. 저장소 사용이 불가능하면 다음 방문에 다시 보일 수 있다.
- 휴대전화 아이콘은 시작 안내를 닫은 뒤 사용자가 전화·확인 의사를 표현하거나 상대가 송금·링크·정보 제공·전화 등 구체적 행동을 요구할 때 **한 번만** 부드럽게 강조하며, 사칭/정상 신원이나 행동 요구에 따라 달라지지 않는다.
- 송금/정보 제공은 **현재 대사에 실제 요청이 있고 LLM 제안과 서버 가드가 일치할 때에만** 해당 말풍선 안에 행동 버튼으로 표시한다.
- 링크/안내 번호도 **상대가 실제로 메시지에서 제시할 때에만** 말풍선 안에서 클릭 가능하다. 링크는 실제 외부 URL이 아닌 안전한 가상 페이지를 보여준다.
- 링크 열기와 정보 제출은 서로 다른 기록이며, 링크에서 돌아오기만 하면 정보 제출로 간주하지 않는다.
- **모의 휴대전화에서 기존 연락처나 공식 앱·번호를 직접 선택하면 행동과 확인 결과가 기록되지만 대화는 즉시 종료되지 않는다.** 확인 결과를 보고 다시 문자로 돌아와 대화를 이어가거나, 명시적으로 종료할 수 있다.
- 상대가 안내한 번호로 전화하거나 메시지 안의 링크를 여는 것은 **독립 확인이 아니며**, 이후 별도의 공식 채널 확인을 선택할 수 있다. 기존 출처와 문자를 보낸 번호는 서로 다른 선택지로 제공한다.
- "전화해 볼게요" 같은 **발언만으로 확인 완료 처리하지 않는다.** 공식 경로 확인 버튼 선택에만 확인 이벤트를 기록한다.
- 진짜 연락도 확인 없이 위험한 요청에 응하면 개선할 행동으로 안내한다.
- 사칭임을 운 좋게 맞혀도, 독립 확인 행동을 수행했다고 판정하지 않는다.
- **신원 추측 질문을 훈련 종료의 필수 단계로 요구하지 않는다.** 대화가 끝나면 행동 피드백으로 바로 이동할 수 있다. 서버의 구형 guess 필드는 호환성을 위해 판단 보류로 전달한다.
- 결과 화면은 **가상 상대의 실제 정체가 아니라, 사용자가 실제로 선택한 대응 행동**을 가장 먼저 보여 준다. 대화 초반에 종료한 경우에는 이후의 요청 대응을 충분히 관찰하지 못했다고 별도 안내한다.
- 결과는 두 페이지로 나눈다. 1페이지는 **행동 총평 → 실제로 잘한 행동 문장 → 다음에 해야 할 행동 문장**, 2페이지는 **다음에 실천할 행동 → 안전 약속 세 가지** 순으로 보여준다. 상대의 가상 정체와 사건 설정은 2페이지 후반의 펼치기 항목에서만 선택적으로 확인할 수 있다. 전체 선택 기록·세부 근거·안전 약속 설명·가족 질문은 사용자가 직접 펼치는 disclosure에서 확인할 수 있으며, 공유와 가족 질문 수정 기능은 유지한다. 사기 여부를 맞혔다고 올바른 행동이 되지는 않는다.
- 가족/기관 상황에 따라 기존 번호 확인·금전/정보 제공 보류·가족과 상의하기 등의 구체적인 약속을 반복한다.
- "이번에 실천" 문구는 서버가 보관한 **실제 선택 이벤트**로 확인된 경우에만 표시한다. 사용자의 "확인할게요"라는 문자 자체는 이행 증거가 아니다.
- 가족 확인 질문이 이 브라우저에 저장돼 있으면 결과에서 그 질문을 보여 준다. 답은 앱의 공유 메시지에 포함하지 않으며, 가족 간 실제 합의·질문 정답 여부를 검증했다고 주장하지 않는다.
- "가족에게 안전 약속 공유하기"는 사용자 동작에 의해서만 운영체제 공유 시트 또는 클립보드 복사를 실행한다. 공유 메시지에는 약속 원칙만 담고, 가족 확인 질문과 답은 모두 제외한다. 사용자 브라우저의 가족 질문은 서버 AI 대화로 전송하지 않는다.
- 가상 정체·확인 증거는 행동 피드백을 본 뒤 사용자가 넘어간 안전 약속 화면의 선택적 펼치기 항목에 제공한다. 실제로 실행하지 않은 확인 행동을 했다고 주장하지 않는다.
- 피해 예방 효과의 실증적 검증이나 개인의 위험도 진단을 주장하지 않는다. 여러 훈련에 걸친 행동 변화 지표는 이번 구현에 포함되지 않는다.

## 서버와 보안
- Next.js Node API /api/real-training에 서버가 시나리오·Gemini/Groq 공급자 전환·대화 감독·행동 평가를 통합한다.
- AES-256-GCM으로 봉인한 45분 수명 토큰에 세션별 사건 앵커 번호와 대화 상태를 함께 저장. 시나리오 정체가 브라우저 평문에 노출되지 않고, 사용자가 결과를 변조할 수 없다.
- 교육용 MVP로서 다중 인스턴스 전역 레이트리밋이나 서버 측 토큰 재사용 방지는 미구현. 정식 서비스에서는 데이터베이스 세션·재사용 방지·관측성 강화 필요.
- 모델 응답은 reply+actions+dialogue 구조화 JSON으로 받는다. 행동·종료·중복 응답에 대해서만 2차 의미 검수를 호출해 불필요한 지연을 줄인다. 서버는 1차 배우 대사에서 증명되지 않는 행동을 제거하며, 감사 모델이 새 행동을 단독 생성할 수 없다. 서버는 봉인된 메시지 및 actionId를 통해 실행할 수 있는 가상 행동을 제한한다.
- 모델 오류는 가짜 Gemini 대사로 대체하지 않고 명확하게 재시도 안내.
- 외부 사이트에서 브라우저를 통해 API를 호출하지 못하도록 JSON Content-Type과 Origin 검사, 기본 IP 레이트 리미터 적용. (운영용 보안 완성은 아님.)
- 실제 계좌/연락처/이메일/링크처럼 보이는 문자열 입력 차단; 서버 내 실제 송금·녹음·통화 기능 없음. 개인정보를 입력하지 말라고 화면에 안내.

## 배포 전 필수 설정
**Dokploy의 mikkialert 서비스 환경변수에 서버 전용** GEMINI_API_KEY (또는 TRAINING_GEMINI_API_KEY), 선택적으로 GROQ_API_KEY를 등록하고 Save → Deploy 한다. 기존 Supabase Edge Function의 Secret은 Dokploy 컨테이너로 자동 전달되지 않는다.
- 선택: GEMINI_MODEL, GROQ_MODEL, LLM_PROVIDERS. 모델의 기본값은 공용 공급자 모듈에 정의돼 있다.
- 권장: TRAINING_SESSION_SECRET을 고정해 LLM 키 변경이 기존 실전 대화 토큰을 무효화하지 않도록 한다.
- NEXT_PUBLIC 접두어를 붙이지 말 것. 공개 GitHub/스크린샷에 키를 저장하지 말 것.
- GitHub의 main 반영만으로는 새로운 API 키가 생성되지 않음.
- 배포 후 정상/사칭 케이스 양쪽, 공식 확인, 결과, 재연습, 모바일 입력 등을 직접 검증해야 함.
