# 미끼주의보 문자 훈련 채팅 엔진 v3 (2026-11-05)

## 목표
AI 대화가 자연스럽더라도 훈련의 **안전 행동과 채점은 AI의 말에 의존하지 않는다.**
특히 정상인이 안전 확인 절차를 먼저 알려 주는 일이 없도록 하고, 학습자가 스스로 독립 확인을 선택할 수 있게 한다.

## 구성
1. **시작:** `SCENARIOS`의 정상/사칭 6개 중 하나를 고른 후, 해당 주제의 사건 앵커 3가지 중 하나를 무작위로 선택한다. `caseVariant`는 AES-GCM 봉인 세션 안에만 저장된다. 같은 주제의 정상/사칭은 같은 앵커 후보를 사용한다. 첫 문자는 고정 `scenario.opening`이 아니라 숨겨진 정체를 제외한 동일 조건에서 AI가 작성한다.
2. **답장:** LLM 배우는 시나리오·선택된 사건 앵커·지난 대화 요약·전체 대화 기록·사용자 의도에 따라 `reply/actions/dialogue`를 만든다. 앵커는 발신자의 설명/주장일 뿐 실제 확인 증거가 아니다. 부가 거래정보·업체명·식별번호는 꾸며내지 않는다.
3. **행동 버튼:** 실제 배우 대사에 행동 요청이 명시돼야 한다. 2차 검수는 배우가 제안한 `kind/origin`을 확인할 수는 있지만 새 행동을 단독으로 추가할 수 없다. 메시지 표면적 근거가 없는 경우 서버에서 버린다. 서버의 `actionId` 검증과 `.example` 가상 링크 정책은 유지한다.
4. **학습자 주도 행동:** `···` 메뉴의 **다른 경로로 직접 확인하기**는 상대가 한 말을 필요로 하지 않는다. 상황별 준비된 가상 독립 확인 결과를 보여주고, `verify`를 서버 이벤트로 기록한 뒤 종료한다. **가족에게 연락**은 가족 시나리오에서는 독립 확인이고, 금융/배송 시나리오에서는 단순 가족 상담으로 분리한다. 채팅에 '확인했어'라고 입력한 것만으로 이벤트가 생기지 않는다.
5. **대화 종료:** 일반 답장에는 별도 LLM 감사 호출을 생략한다. 행동 제안·종료 제안·중복 응답이 있을 때만 감사한다. 검수가 명시적으로 미종료라면 종료하지 않는다. 감사 실패 시 확실한 종료 응답에 한하여 최소 4턴(이전부터 closing이면 3턴)부터 보수적으로 종료한다. 미해결 요청·질문·행동 버튼은 조기 종료를 막으며 최대 8턴이면 종료한다.
6. **결과:** PR #15의 행동 우선 2페이지 결과 화면을 유지하고, 발화 주장과 실제 클릭·모의 이체·확인 이벤트를 구별한다.

## 회귀 테스트
- `npm run typecheck`, `npm run test:training`, `npm run test:backend`, `npm run build`
- 6개 시나리오의 독립 확인 버튼과 정체별 확인 결과, 메시지 내 위조 actionId 거절
- 사건 앵커 3×6 조합, 정상/사칭 간 일관성, 처음 메시지의 정체 비노출
- 감수 모델의 환각 행동, 요청 없는 버튼, 부정문, 잘못된 전화 출처, 정상 인물의 인증 경로 제공 방지
- 감사 장애 시 안전한 종료, 질문/미해결 요청/검수 불일치 차단
- 테스트는 **규칙·통합 경계** 검증이며 실제 Gemini/Groq의 자연스러움에 대한 품질 보장은 아니다. 운영 API 키를 이용한 다중 턴 실제 대화/실기기 측정은 후속 검수 필요.

## 한계
- 사건 앵커는 신원을 특정할 수 있는 실데이터가 아닌 교육용 설정이다. 리얼리즘과 세부 조회 사이의 한계가 있다.
- 두 모델이 동시에 같은 의미를 오해하거나 단어 표현이 다양할 경우 행동 버튼을 놓칠 수 있다. 반대로 근거 있는 대사만 버튼으로 보이는 보수적인 정책을 우선한다.
- 검수 호출 실패 시 일부 대화는 최대 턴까지 갈 수 있다.
- 부하 측정, 실제 모델 응답 지연, 채팅 주관적 품질은 자동화된 정적 테스트만으로 확인되지 않는다.
- 서버 세션은 봉인 토큰이며 정식 DB 재생 방지·분산 rate limit은 미구현이다.
