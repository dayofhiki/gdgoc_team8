# 미끼주의보 실전 대응 훈련: 상황 인식형 대화 엔진 v2

## 설계 목적
대화가 끝났는데도 AI가 "나중에 연락할게"를 반복하는 문제를 줄이고, 초기에 정의된 가족/택배/은행 시나리오를 실제 피해 상황에 가까운 불확실성으로 표현한다.

**실제 피해자의 녹취 원문을 수집·재배포하거나 이를 모델에 넣은 것은 아니다.**
공개 사례의 유형별 특징을 교육용 규칙으로 재구성했다. 단순히 새로운 금융사기 대본 20건을 추가한 것은 아니다.

## 검토한 자료와 사용 범위
1. [배승희·최민경·이혜용(2023), 「보이스피싱 대화의 대화 원형 연구: 수사기관 사칭형을 중심으로」](https://journal.kci.go.kr/socioling/archive/articleView?artiId=ART003041851): **수사기관 사칭형** 실제 대화를 분석하여 기능 단계를 제시함. 접근→범죄 연루 협박→사회적 고립→위계 강화→인출 유도→인출 확인. 이 6단계를 *모든 유형에 기계적으로 적용하지 않음*. 논문 초록을 참고했으며 개별 대화 원문을 추출한 것으로 주장하지 않는다.
2. [경찰청 피싱안심SOS, 피싱 시나리오](https://www.counterscam112.go.kr/bbs009/board/boardList.do): 택배/카드배송/기관 사칭 등 유형 및 실제 사례 기반의 안내 목록. **실제 사례를 기반으로 제작된 시나리오**와 익명화된 원본 녹취를 동일시하지 않음.
3. [피싱 예·경보](https://www.counterscam112.go.kr/bbs003/board/boardList.do): 최근 유형에 대한 경보 목록. 매월 달라지는 전술을 보완하는 참고용 자료.

가족/택배/은행 세 원형의 사례 요약 정보는 src/lib/trainingDialogue.ts의 CASE_GUIDES에 보관.
시나리오별 독립 검증 결과 및 정체는 기존 src/lib/realTraining.ts에 보관.

## 아키텍처
- **배우(LLM)**: 현재 신원/사실관계/대화 기록/지난 상태를 기반으로 다음 대사를 생성한다.
  정해진 1~2문장 강제나 "매번 요구 강화" 규칙은 없다.
- **행동 추출(LLM + 서버)**: 답변에 실제로 제안한 앱/전화/링크/송금/정보 입력을 별도로 추출한다. URL은 예약된 .example 도메인으로만 표시한다.
- **대화 검수(독립 LLM 호출)**: 마지막 사용자 의도/대화가 끝났는지/남은 요청이 있는지 등을 구조화한다. 기존 행동 검수 호출을 재사용하므로 제3의 네트워크 요청을 늘리지 않았다.
- **감독(결정적 서버 규칙)**: 모델 2개가 종료에 동의 + 미해결 요청 없음 + 사용자 응답이 종료에 부합 + 최소 2턴 + 위험행동 제안 미진행 조건을 확인한다. 반복되는 인사 3회는 제한 조건에서 중지하며, 최대 8턴이면 종료.
- **평가(서버)**: 독립 확인과 위험 행동은 실제로 UI에서 선택된 봉인된 행동 이벤트만 인정한다. 대화 종료나 "공식 앱으로 확인할게"라는 발언 자체는 검증 완료가 아니다.

### 훈련 상태
실전 채팅 상태 토큰에 아래 필드가 포함된다. 서버 AES-GCM 암호화 상태이며 클라이언트의 자유 입력으로 값을 변경할 수 없다.

- dialogue.stage: contact/context/request/closing
- dialogue.hasPendingRequest: 아직 남은 행동 요청
- dialogue.lastSpeakerMove / lastSummary: 대화 맥락
- dialogue.lastReply / repeatCount: 반복 징후
- endReason: natural/turn_limit/action (종료 시만)

마지막 메시지가 이미 인사였고 학습자의 발화가 단순 응답이면, 배우는 **빈 reply를 생성**하고 서버가 종료시키는 것도 허용한다. 이 경우 추가 "잘 자" 등을 만들어내지 않는다.

### 사용자 경험
자연 종료 시 마지막 대화를 그대로 보이며 입력창 대신 "내 대응 결과 확인하기" 버튼을 표시하고, 사용자가 눌렀을 때 최종 판단으로 이동한다. 사기 여부는 최종 결과까지 숨긴다.

### 운영 검증
CI에서 node:test로 정상 종료/성급한 종료/미해결 요청/두 모델의 불일치/반복 대화/턴 제한/정답 누출 없는 채점을 검사한다. TypeScript와 프로덕션 빌드를 실행한다.

**한계**
- 정적 회귀 테스트 통과와 실제 대화의 자연스러움 향상은 서로 다르다.
- 현재 공개 자료를 근거로 20~30개의 원본 전사 대화셋을 구축하지 않았다. 실제 녹취 확보, 저작권 확인, 개인정보 비식별화, 전사 품질 검증은 후속 연구 작업이다.
- AI의 구조화 상태 판정에 오류가 있을 수 있으므로 실제 사용자 테스트, 전문가 검수 및 반복 샘플링이 필요하다.
- 모델 감사 호출이 실패하면 조기 종료는 보수적으로 차단하고 최대 턴 제한으로 종료한다.
- API의 토큰 봉인 방식은 MVP 구조를 유지한다. 다중 인스턴스 세션 재생, 운영 관측성은 별도 인프라 설계가 필요하다.
