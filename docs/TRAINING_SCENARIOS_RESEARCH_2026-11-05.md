## 대화 생성 원칙

1. 모든 주제에서 **정상/사칭 쌍은 동일한 첫 메시지 생성 조건**을 사용한다. 첫 문자에서는 송금·링크·특정 번호 등 정답의 단서를 미리 주지 않는다.
2. 첫 시작 시 해당 주제의 세부 정황 3개 중 1개를 선택하고, 서버에 봉인한 상태로 유지한다. 인물의 주장과 시스템의 실제 확인 결과는 구분한다.
3. 매 턴 **사용자의 마지막 질문에 먼저 대답**한다. 같은 금액·링크·요구를 반복하지 않는다. 모르는 신상·거래내역·차량번호·검사결과·채용 조건은 만들어내지 않는다.
4. 정상인도 사용자의 선택을 존중하되 정답인 독립 확인 방법을 먼저 알려주지 않는다. 단, 실제 삶에서 가능한 용건과 감정은 자연스럽게 표현한다.
5. 사칭자는 관계, 절차, 급박함을 상황에 맞게 연기할 수 있다. 그러나 실제 URL·계좌·전화번호·인증정보를 생성하지 않는다. 제안된 가상 행동은 메시지와 서버가 검증한 `actionId`로만 실행한다.
6. 독립 확인, 송금, 링크 열람, 정보 전송은 **모델의 말**이 아니라 서버에 기록된 실제 가상 행동 이벤트만 인정한다. 실질적 요구 이후 사칭이 독립적으로 확인되면 반복 대화 대신 종료한다.

## 대화 흐름 점검 예시 (실제 자료의 원문 인용이 아님)

- **청첩장:** 결혼 소식 전달 → 수신자가 초대 배경을 질문 → 정상인이라면 일상적인 반응, 사칭자라면 가상 초대장 확인을 제안할 수도 있음 → 사용자가 기존 연락처를 이용하면 결과에 따라 대응.
- **부고:** 조심스러운 연락 → 수신자가 소식의 출처를 묻기 → 확인되지 않은 고인·빈소·일정을 지어내지 않음 → 필요할 때만 안내 확인을 요청.
- **교통 고지:** 교통 안내 목적 → 수신자가 위반 내역/차량을 질문 → 조회되지 않은 세부정보를 주장하지 않음 → 가상 조회 링크 요구 여부와 공식 채널 선택을 관찰.
- **대출:** 상품 상담 → 금리·기존 채무 확인 질문 → 정상이면 승인을 보장하지 않음 / 사칭이면 선입금 제안 가능 → 사용자 거절·독립 확인 시 불필요한 독촉 중단.
- **일자리:** 업무 소개 → 지원 경위·근무조건 질문 → 정상 채용 또는 가상 지원 절차 유도 → 실제 인증정보 입력은 하지 않음.
- **건강검진:** 안내 목적 전달 → 예약·검진 관련 질문 → 검사결과·질병을 꾸며내지 않음 → 정상 문의 또는 가상 조회 링크 유도.

## 진입 플로우

`/roleplay` → `/roleplay/mode` → 실전 대화 선택 시 `/roleplay/select`

- **추천:** `/roleplay/chat`에서 서버가 주제 9개 중 하나를 무작위로 뽑고, 해당 정상/사칭을 다시 무작위로 고른다.
- **직접 선택:** `/roleplay/chat?topic=<topic-id>`에서 서버가 공개 주제만 확인하고, 정상/사칭은 역시 서버에서 무작위 선택한다.
- **결과:** 위험 행동의 실제 기록과 사용 가능한 행동 문장 중심으로 피드백. 상세 근거는 사용자가 원할 때 펼쳐 본다.
- **검증 한계:** CI의 타입 검사·규칙 회귀 테스트와 실제 LLM이 생성하는 여러 턴의 자연스러움은 별개다. 운영 API 키로 실제 대화 및 모바일 사용자 테스트를 추가해야 한다.
