## 대화 생성 원칙

1. 모든 주제에서 **정상/사칭 쌍은 동일한 첫 메시지 생성 조건**을 사용한다. 첫 문자에서는 송금·링크·특정 번호 등 정답의 단서를 미리 주지 않는다.
2. 첫 시작 시 해당 주제의 세부 정황 3개 중 1개를 선택하고, 서버에 봉인한 상태로 유지한다. 인물의 주장과 시스템의 실제 확인 결과는 구분한다.
3. 매 턴 **사용자의 마지막 질문에 먼저 대답**한다. 같은 금액·링크·요구를 반복하지 않는다. 모르는 신상·거래내역·차량번호·검사결과·채용 조건은 만들어내지 않는다.
4. 정상인도 사용자의 선택을 존중하되 정답인 독립 확인 방법을 먼저 알려주지 않는다. 단, 실제 삶에서 가능한 용건과 감정은 자연스럽게 표현한다.
5. 사칭자는 관계, 절차, 급박함을 상황에 맞게 연기할 수 있다. 그러나 실제 URL·계좌·전화번호·인증정보를 생성하지 않는다. 제안된 가상 행동은 메시지와 서버가 검증한 `actionId`로만 실행한다.
6. 독립 확인, 송금, 링크 열람, 정보 전송은 **모델의 말**이 아니라 서버에 기록된 실제 가상 행동 이벤트만 인정한다. 실질적 요구 이후 사칭이 독립적으로 확인되면 반복 대화 대신 종료한다.

## 대화 흐름 점검 예시 (실제 자료의 원문 인용이 아님)

- **청첩장:** 결혼 소식 전달 → 수신자가 초대 배경을 질문 → 정상인이라면 일상적인 반응, 사칭자라면 가상 초대장 확인을 제안할 수도 있음 → 사용자가 기존 연락처를 이용하면 결과에 따라 대응.
- **부고:** 조심스러운 연락 → 수신자가 소식의 출처를 묻기 → 확인되지 않은 고인·빈소·일정을 지어내지 않음 → 필요할 때만 안내 확인을 요청.
- **교통 고지:** 교통 안내 목적 → 수신자가 위반 내역/차량을 질문 → 조회되지 않은 세부정보를 주장하지 않음 → 가상 조회 링크 요구 여부와 공식 채널 선택을 관찰.
- **대출:** 상품 상담 → 금리·기존 채무 확인 질문 → 정상이면 승인을 보장하지 않음 / 사칭이면 선입금 제안 가능 → 사용자 거절·독립 확인 시 불필요한 독촉 중단.
- **일자리:** 업무 소개 → 지원 경위·근무조건 질문 → 정상 채용 또는 가상 지원 절차 유도 → 실제 인증정보 입력은 하지 않음.
- **건강검진:** 안내 목적 전달 → 예약·검진 관련 질문 → 검사결과·질병을 꾸며내지 않음 → 정상 문의 또는 가상 조회 링크 유도.

## 진입 플로우

`/roleplay` → `/roleplay/mode`에서 세 가지 진입을 선택한다.

- **실전 훈련:** 예고 없이 `/roleplay/chat`으로 들어가며 서버가 9개 중 한 상황을 무작위로 정한다. 화면에 "추천"이나 "무작위"라는 설명 대신 **"어떤 연락이 올지 모릅니다"**라는 실제 생활의 맥락을 제시한다.
- **상황별 연습:** `/roleplay/select`에서 주제를 고른 후 `/roleplay/chat?topic=<topic-id>`으로 이동한다. 사용자에게는 주제만 알려준다. 현재 실전/상황별 훈련에서는 실제 잘못된 행동 요구가 발생하는 역할을 선택하며, 정상 역할 데이터는 별도 연구·테스트에 유지한다.
- **사례로 배우기:** `/roleplay/case`에서 기존 사례를 관찰하며 실제 행동이 필요한 지점을 익힌다.
- **결과:** 의무적인 신원 추측 질문 없이 **실제 선택한 행동 → 다음에 실천할 안전 약속**으로 이어진다. 가상 연락의 정체/사건 설정은 선택적으로 펼쳐 볼 수 있다.
- **검증 한계:** CI의 타입 검사·규칙 회귀 테스트와 실제 LLM이 생성하는 여러 턴의 자연스러움은 별개다. 운영 API 키로 실제 대화 및 모바일 사용자 테스트를 추가해야 한다.

## 2026-11-05: 행동 선택 중심 개편

- 단순히 **'거래가 맞는지 은행 앱에서 확인해 주세요'**만 반복하는 대화는 구별할 선택지가 없어 훈련 대상에서 제외했다. 현재 9개 유형 모두 후속 대화에서 돈·개인정보·문자 링크 등 **거절하거나 다른 경로로 확인해야 할 요청**이 등장하도록 제한한다.
- 첫 메시지는 계속 AI가 중립적으로 생성한다. 대화가 진행되면 사용자의 질문에 먼저 답하고, 그 후에 위험한 요구를 제시한다. 두 번째 답변에서도 유해 요청이 나오지 않으면 해당 답변을 한 번 재생성한다.
- 금융 시나리오는 **모바일 상품권 48만 원 / 온라인 정기결제 27만 원 / 간편결제 36만 원** 중 하나를 세션마다 가상 정황으로 고정한다. 해당 거래가 실제로 있었다는 주장이 아니다. '무슨 거래인가요?'라고 물으면 같은 종류와 금액을 설명해야 한다.
- 단순 확인 안내, 정체 소개, 실제로 사용하지 않은 공식 채널 확인은 평가 근거가 아니다. 휴대전화 강조는 **사용자 선택 시점에 대한 중립적 접근성 안내**이며 사기 판별 힌트가 아니다. 텍스트의 '본인 확인 부탁드립니다'와 실제 데이터·링크 제출 요청 모두 감지한다.
- 실제 개인 계좌, 전화번호, 웹사이트, 비밀번호를 모델이 생성하지 않는다. 위험 행동 버튼은 기존의 서버 봉인된 `actionId` 및 실제 배우 발화·감사 결과와 일치하는 경우에만 보여준다.
- 실제 Gemini/Groq 다중 턴의 자연스러움과 텍스트 패턴의 오탐·누락은 정적 CI로 보장되지 않는다. 실제 모델 대화와 모바일 화면 검수가 필요하다.
