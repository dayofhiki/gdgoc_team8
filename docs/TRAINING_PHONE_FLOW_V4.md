# 실전 문자 훈련: 휴대전화 기능 패널 v4

## 설계 원칙

사용자가 상대의 문자를 읽고 **직접 행동을 찾아 선택하는 훈련**이다. 첫 메시지 아래에 '정답 행동' 버튼을 제시하지 않는다. 현실에서는 첫 메시지만으로 확인이 필요한 경우도 있으므로, 기능을 사용하기 위한 최소 턴 수를 강제하지 않는다. 대신 **외부 확인 행동이 곧 훈련 종료가 되지 않도록** 대화와 행동을 분리한다.

## 진입과 주목 효과

- 상단 오른쪽의 휴대전화 아이콘에서 언제든지 모의 기기를 열 수 있다. 첫 화면은 연락처, 전화, 앱, 송금 네 기능이며 '공식 경로 확인'을 직접 노출하지 않는다. 메시지는 패널을 닫으면 곧바로 다시 볼 수 있어 중복 기능으로 두지 않는다.
- 사용자가 전화·확인·조회 등 외부 기능의 사용 의사를 밝히거나 **상대가 송금·링크·정보 제공·전화 등의 구체적인 행동을 요구하는 순간**, 첫 해당 시점에 **한 번만** 1.9초 동안 테두리·배경이 아주 약하게 변한다. 단순히 두 번 대화했다는 이유로 강조하지 않는다.
- 정상/사칭 여부, 위협 문구, AI 행동 요청의 종류에 따라 강조를 차등 표시하지 않는다. 강조는 위험 경보나 정답 힌트가 아니다.
- 움직임 감소 설정에서는 애니메이션 대신 정적인 약한 강조를 제공한다. 화면을 가리는 큰 안내 말풍선은 제거한다.

## 모의 휴대전화 선택

| 화면 | 항목 | 서버 행동 | 효과 |
| --- | --- | --- | --- |
| 연락처 | 저장된 가족 연락처 | `family_contact` + `saved_family` | 가족 관련 상황에서는 확인, 다른 상황에서는 단순 상담 |
| 연락처/전화 | 현재 문자 발신자·최근 번호 | `verify_sender` + `recent_sender` | 발신자의 주장만 확인; 독립 신원 확인이 아님 |
| 전화 | 직접 찾은 기관 대표번호 | `verify` + `official_directory` | 택배/은행 상황의 독립 확인 |
| 설치된 앱 | 은행 앱 또는 택배 앱 | `verify` + `bank_app`/`delivery_app` | 해당 상황에 일치할 때만 독립 확인, 관련 없는 앱은 로컬 안내만 |
| 송금 | 이전 문자에서 실제 요청된 모의 송금 대상 선택 → 최종 확인 | 봉인된 메시지 `actionId`와 `sourceIndex`로 `comply` | 송금 의사가 명시되면 행동을 기록하고 훈련 종료, 실제 금전 이동 없음 |
| 문자에서 안내한 번호 | 연락처가 아닌 상대방 제공 연락처 선택 | 봉인된 메시지 `actionId`와 `sourceIndex`로 `verify_sender` | 검증 아님, 문자 대화로 돌아와 계속 가능 |

- 모의 전화/앱 실행 결과는 패널에서 확인하고 문자로 돌아올 수 있다. **초반의 독립 확인, 가족 연락, 발신번호 전화는 곧바로 대화를 닫지 않는다.** 단, 앞서 상대가 송금·개인정보·링크 등 구체적인 요구를 했고, 독립 확인으로 그 연락이 사칭임이 확인된 경우에는 충분히 연습한 것으로 판단해 종료한다. 확인 결과는 대화에 남기고 사용자가 결과 보기 버튼을 직접 누르도록 한다.
- 송금은 **AI가 실제 대사에서 요청하고 서버가 봉인한 행동이 있을 때만** 패널의 요청 목록에 나타난다. 요청이 없으면 아무것도 실행되지 않는다. 두 단계(요청 선택 → 모의 송금 최종 확인)를 거친다. 문자 하단에는 패널에 없는 링크 열람/정보 제출 등만 남긴다.
- 새 훈련 시 기능 안내 시트가 나타나며, 반복을 원치 않으면 **다음부터 이 안내 보지 않기**를 선택할 수 있다. 결과는 키워드 우선으로 보여주되 상세 근거는 펼칠 수 있다.
- 송금·개인정보 제출, 사용자의 명시적인 대화 중단, AI의 자연 종료, 최대 8턴 도달은 이전대로 종료 가능하다.
- 행동 요청을 따른 링크·송금·정보 제공은 기존 메시지별 봉인된 `actionId` 검증을 유지한다.
- 서버는 휴대전화 행동의 `method`를 시나리오에 대조하고 재사용이나 출처 위조를 거부한다. 직접 `verify`만 전송해 결과를 얻는 단축 호출을 허용하지 않는다.
- 대화 완료 시, 실제 위험 요청이 나왔는지와 초기 종료 여부를 구분한다. 대응을 관찰하지 않은 경우에는 평가의 범위를 사용자에게 알려준다. 조기에 외부 확인을 한 것 자체를 잘못된 행동으로 평가하지 않는다.

## 검증 및 제약

- 자동 테스트: 정상/사칭 6개 상황에서 경로별 확인, 최근 발신번호의 미확인 판정, 메서드 위조/중복 거절, 초기 확인 비종료, 이른 종료 시 한정된 피드백, UI 연결·접근성 관련 정적 단언.
- 실제 통화, 문자 수신, 앱 실행, 금융정보 입력은 하지 않는다. 모든 장면은 웹 내부의 모의 화면으로 동작한다.
- CI 테스트는 실제 LLM이 5~8턴 동안 충분히 자연스럽게 진행되는지, 화면의 체감 품질·응답속도를 보증하지 않는다. 실사용 검수는 별도로 필요하다.

## 종료 정책 (2026-11-05 추가)

- **행동 전 상태 관찰:** 송금·링크·개인정보 제공 등 구체적 요구가 등장했는지 서버의 봉인된 행동 제안/발화로 판단한다. "수리비가 얼마인지 몰라" 같은 단순 상황 설명만으로는 훈련 목표가 달성되지 않는다.
- **확인 후 종료:** 독립 확인 결과가 사칭과 맞아떨어지고, 이미 구체적인 요구가 관찰됐다면 이 시점에서 대화를 종료한다. *초반에 독립 확인만 한 경우*에는 기존대로 대화할 수 있다.
- **확인보다 거절:** 요청을 받은 후 "돈 안 보낼게", "그만 연락해", "차단할게"와 같이 사용자 스스로 명백하게 거절하고 관계를 끊었다면 상대에게 추가로 변명하거나 반복할 기회를 주지 않는다. "너 사기꾼이지?" 같은 확인 질문만으로는 종료하지 않는다.
- **먼저 확인한 경우:** 초반에 사칭임을 독립 확인하고 잠시 대화를 이어 갔는데 추후 실제 위험 요청이 등장했다면 그 시점에 종료한다.
- **결과 화면:** `resolved`는 직접 확인 결과가 남은 상태에서 사용자에게 문자 로그를 읽을 기회를 주고, 독립 확인까지 완료한 경우에는 불필요한 정체 맞히기 질문을 건너뛰어 행동 피드백으로 바로 이동할 수 있다.
- **반복 방지:** 같은 내용의 답변이나 금전 요구가 세 차례 가까이 반복되고 사용자에게 미해결 질문이 없다면, AI가 아직 요청이 남았다고 표시하더라도 대화를 종결하고 반복 종료를 설명하는 안내를 남긴다. 새로운 질문이 있으면 섣불리 끝내지 않는다.
- **나머지 종료 조건:** 실제 모의 송금·정보 전송, 훈련 중단, AI의 자연스러운 마무리, 최대 8턴 제한은 유지된다.
